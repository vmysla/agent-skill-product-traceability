Build a Tetris game as a single static HTML file named `index.html` in the repo root.

Requirements:
- A playfield 10 columns wide and 20 rows tall. Row 0 is the top row.
- The seven tetrominoes: `I`, `O`, `T`, `S`, `Z`, `J`, `L`. Give each one its own colour.
- A piece spawns at the top and falls one row at a time under gravity.
- When a piece can no longer fall, it locks in place and the next piece spawns.
- The player can move the falling piece left and right, soft drop it (one row down), and hard
  drop it. A hard drop sends the piece straight down to the lowest position it can reach and
  locks it there immediately.
- Show the score, the level and the number of lines cleared. The score is 0, the lines
  cleared is 0, and the level is 1.

Constraints (these hold for the entire project):
- ONE file: `index.html`. Inline CSS and JS. No frameworks, no build step, no CDN links, no
  network requests.
- The game must work when opened directly from the filesystem.
- Rendering must be synchronous. After any state change the DOM must already show the new
  state. Do not defer drawing to `requestAnimationFrame` or to a timer — the tests read the
  DOM immediately after driving the game, and a deferred draw will never arrive.

Test contract — the grader depends on these exact attributes, so use them verbatim. Every
piece the game draws, on the board or anywhere else, must be drawn as DOM elements coloured
with CSS — never on a `<canvas>` and never as an image — because the grader reads each piece's
colour out of computed styles.
- `data-testid="board"` — the playfield container
- `data-testid="cell"` — one board cell. There are exactly 200 of them. Each carries:
  - `data-row="0".."19"` and `data-col="0".."9"`
  - `data-filled="true"` when something is drawn in that cell, `"false"` when it is empty
  - `data-piece` — the letter of the piece drawn there, or `""` when the cell is empty
- `data-testid="score"` — the score, as a number in its text
- `data-testid="level"` — the level
- `data-testid="lines"` — lines cleared

Test control surface — also part of the contract, and also verbatim.

A falling-block game cannot be tested as it stands: the piece order is random and gravity runs
on real time. So the app must expose `window.__tetris`, which exists so automated tests can
drive the game without waiting on a clock or guessing what comes next.

    window.__tetris.newGame(queue)
      Starts a fresh game: empty board, score 0, level 1, lines 0, status "running".
      `queue` is an optional array of piece letters, e.g. ["I","O","T"]. Pieces are taken from
      it in order — the first becomes the falling piece, the rest are the upcoming pieces.
      When the array runs out the game falls back to its normal random generator. Called with
      no argument it starts a normal random game.

    window.__tetris.setQueue(queue)
      Replaces the upcoming pieces with the given array. The piece currently falling is left
      alone.

    window.__tetris.setBoard(rows)
      Replaces the locked cells. `rows` is an array of 20 strings of 10 characters each, top
      row first: "." is an empty cell, and any of I O T S Z J L is a locked cell of that
      piece's colour. It sets them exactly as given and changes nothing else. The falling
      piece is not affected.

    window.__tetris.tick(n)
      Advances the game by exactly n gravity steps, immediately, as if n gravity intervals had
      elapsed. `n` defaults to 1. A gravity step here must be the identical step the real
      timer runs — the same function, not a second copy of the logic.

    window.__tetris.input(action)
      Performs one player action, exactly as if the player had done it. The actions are
      "left", "right", "softDrop" and "hardDrop".

    window.__tetris.getBoard()
      Returns the locked cells in the same shape `setBoard` accepts: 20 strings of 10
      characters, top row first, "." for empty. It must be read out of the game's real board
      state — the same data the renderer draws from, not a separate bookkeeping copy. The
      falling piece is NOT included.

    window.__tetris.getState()
      Returns a plain object:

        {
          current: { type, cells } | null,
          next: [ letters, soonest first ],
          score, level, lines,
          status: "running"
        }

      `current.type` is the piece letter. `current.cells` is an array of `[row, col]` pairs
      giving the falling piece's cells on the board, row 0 at the top. `next` lists the
      upcoming pieces, soonest first.
